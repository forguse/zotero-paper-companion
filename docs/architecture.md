# 架构与扩展约定

论文伴读是原生 Zotero 插件，采用 XHTML、CSS、JavaScript 和注入端口，无前端框架或第三方服务端。插件 ID 为 `paper-companion@local`。界面、平台适配、应用流程、模型协议与持久化分开维护。

## 从哪里开始

| 需要修改的能力 | 首选入口 | 职责 |
| --- | --- | --- |
| Zotero 注册、窗口、PDF、剪贴板与磁盘 | `bootstrap.js`、`native.js`、`sidebar.js` | 组合根与平台适配；提供明确端口，不在这里重新实现业务流程 |
| 模型请求、鉴权快照、返回模型与流解析 | `model-gateway.js`、`core.js` | 网关统一选择与计量请求；纯请求构造和解析留在 core |
| 一次问答的准备、取消、完成与保存 | `chat-service.js` | 从首次异步读取前登记忙碌和完成任务，直到本机保存结束才释放 |
| 会话及历史 | `sessions.js`、`persistence.js` | 共享首次读取、不可变保存快照、归档恢复、按路径排队 |
| 批量设置与未保存草稿 | `settings-panel.js` | 脏字段、Key 状态、双提示词和词库设置；只接收必要的读写与视图端口 |
| 原文提取与检索 | `reading.js` | 本机词法索引、有界缓存、共享提取、多论文材料和引用定位 |
| 阅读范围计划与实际依据 | `reading-scope.js`、`reading-scope-ui.js` | 共用材料选择规则，展示已知状态，不自行读取或推理 |
| 模型预读、重点、公式与词义 | `preread.js`、`insights.js`、`formula.js`、`vocabulary.js` | 各自组织材料、状态和文件，模型调用统一走网关 |
| 论文资料目录与直接编辑笔记 | `paper-files.js`、`note-editor.js` | 原文关联、资料位置、Markdown 编辑和外部修改备份 |
| 计量与明细存储 | `usage.js`、`usage-store.js` | 前者记录接口用量和价格快照；后者管理分段、摘要、迁移和历史分页 |
| 视图 | `panel.js`、`chat-view.js`、`vocabulary-ui.js`、`usage-panel.js` | 页面组合、局部交互与渲染，不持有模型凭据 |
| 可撤销摘记与操作提示 | `note-insertions.js`、`note-receipt-ui.js`、`action-guide.js` | 精确插入撤销、本机保存回执、有界快捷偏好 |
| 用户确认后的卸载清理 | `uninstall-service.js`、`uninstall-ui.js`、`native.js` | 明确清单和确认票、路径及附件保护、暂停写入，最后移除插件 |
| 网页草稿 | `webview.js`、`WebBridgeChild.sys.mjs` | 草稿和附件桥接，始终由用户点击网站发送 |
| 主题、图标、光效和公式排版 | `appearance.js/css`、`ui.js`、`edge-light.js`、`math.js` | 共用四主题与生命周期；动效遵守减少动态及高对比度偏好 |

依赖方向是「界面控制器 → 应用服务 → 模型网关／存储 → 平台端口」。`native.js` 是组合位置，现有公开方法保留为兼容转发。不要将新的通用模型能力放回重点文档服务。

## 模型与任务生命周期

- 打开 Zotero、侧栏或刷新设置仅读取本机状态，不发起模型连接。授权、余额和推理各有明确触发操作。
- 网关在第一个异步步骤前固定提供方、模型、强度、账号和连接代次。授权后、发送前及完成后核对连接；切换账号或断开后不发送旧请求，不静默换模型。
- 所有生产推理必须经计量请求端口；网页草稿不伪装成 API 调用。正文流解析复用已解析事件读取实际模型，避免额外扫描同一条流。
- 问答服务拥有忙碌、取消控制器与完成 Promise。停止也覆盖最初的慢会话读取；关机等待准备、请求及保存收尾。保存失败保留可见答案并支持仅重试本机保存。
- 文档整理和笔记记录失败不把已经完成的模型回答改成失败。自动维护只在明确开启后运行，重点再整理始终手动触发。
- 正常关闭有等待约定，不承诺系统强杀或磁盘断电时全部数据已经落盘。

## 持久化与并发

同一目标文件的文本替换统一经过按路径 FIFO；失败不会使后续任务永久阻塞，不同路径可以独立完成。配置、账号和凭据的读改写另有上层事务；写入队列不等于多文件数据库事务或跨进程锁。

会话仓库合并首次读取，保存时仅序列化一次不可变快照。新建和恢复先保留归档，恢复不会先写空当前会话。未保存会话和可变对象不能作为普通只读缓存随意淘汰。

笔记保持正文直接编辑。发现外部文件变化时先备份原文件，再保存插件稿；备份失败时保留外部文件与未保存稿。这不是协同编辑或不同窗口之间的语义合并。

## 原文缓存与共享提取

只读索引默认最多保留 6 篇，并使用约 12 MiB 的派生数据估算预算；该预算不是 JavaScript 堆内存承诺。超预算索引本次仍可使用，之后可从磁盘恢复，淘汰不删除 PDF、手写笔记或磁盘索引。

提取身份包含论文键、源路径、PDF 指纹和资料目录。同一身份的并发请求共用提取；各调用者有独立取消信号，全部离开才中止底层。已取消但仍等待 PDF 底层返回的任务继续登记并在关闭时排空。写入前复核源文件、指纹和目录，迟到结果不能覆盖新来源。

全文限制为 600 页、200 万字符。当前检索使用词法索引及常用中英术语映射，并非通用跨语言语义检索。文字预读不包含扫描页和图表识别；后续问答使用提要与有界原文，不依赖模型永久记忆全文。

## 用量分段与迁移

`usage-store.js` 只接文件端口，不接触 DOM、模型或凭据。小账本保持旧格式兼容；达到 750 条时将最旧 250 条写成不可变分段，再原子替换 `usage-index.json`。成功后的近期尾部少于 750 条，历史明细缓存最多两段，界面每页读取 30 条。

迁移后保留原 `usage.json`。只有新索引确实不存在才尝试旧格式；损坏 JSON、`null` 或不支持的结构明确报错，不能悄悄退回旧账本并覆盖新历史。先写段、后写索引，提交成功才移除已归档尾部；失败保留所有未保存记录，允许重试，不自动删除孤立段文件。

摘要按提供方、功能和论文累计，保留每条请求的原价格快照；日期变化时先明确显示更新中。历史页有请求版本保护，旧筛选结果不能覆盖新页面。新记录、单价和余额共用存储事务队列；关闭等待写入、日期刷新及在途读取。

这是对原始记录常驻数量和单次写入规模的控制。分段目录、分组摘要和模型名称仍随历史增长；写盘持续失败时，近期尾部允许暂时超预算以保住未保存记录。可变会话的自动释放仍需独立持有契约，不作为此次只读缓存优化的一部分。

## 扩展与验证

新增功能先明确状态所有者、输入上限、取消语义和持久化责任。新增脚本必须同时登记 `bootstrap.js` 或 `panel.xhtml` 的加载顺序，以及 `scripts/build.py` 的运行文件白名单。保留插件 ID、论文键、旧文件名兼容和直接编辑入口。

新增模型提供方除了网关协议，还需模型能力目录、配置入口和计价约定；不得通过失败时静默切换提供方处理不兼容材料。凭据仅由平台端口提供，不写入用量、笔记、日志或安装包。

先运行直接模块测试，再按范围进行隔离原生检查。重点包括 `model-gateway.test.cjs`、`chat-service.test.cjs`、`settings-panel.test.cjs`、`sessions.test.cjs`、`reading.test.cjs` 和 `usage-store.test.cjs`。安装及完整重启单独验证，详见[开发指南](../CONTRIBUTING.md)。原生检查使用合成资料和模拟响应，不代表真实账号、跨平台、超大文库或真实读屏认证。

## 当前边界

设置批量草稿、问答编排及模型协议已有独立模块；`panel.js` 仍组合账号、各功能即时选项、资料迁移和视图状态，未宣称整个界面完全解耦。部分较旧测试仍使用源码片段，新模块采用直接导入与注入端口。

ChatGPT 套餐余量由官方页面查询，插件金额是 API 等价估算。清单保留 Zotero 安装所需的更新地址；更新清单和安装包均可匿名下载时，可使用正常 Zotero 更新，受限下载源需手动安装。下载可用性及更新流程需实际验证，见[更新与服务限制](updates.md)。
