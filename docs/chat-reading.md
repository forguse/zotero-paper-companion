# 对话与阅读交互规格

本文定义面板布局、阅读位置与局部操作的维护约束。使用方法见[使用指南](usage.md#chat)，服务和存储边界见[架构说明](architecture.md)与[模块职责](responsibilities.md)。

## 页面与入口

主导航保持「对话、翻译、笔记、单词本、重点、设置」六个同级工作页。聊天重点与重点再整理使用独立子页。收起工具区、切换页面和进入专注阅读只改变展示，不删除草稿、笔记或材料。

| 区域 | 常态 | 展开或切换后的约束 |
| --- | --- | --- |
| 顶栏 | 品牌、版本与主题入口紧凑展示 | 可展开论文选择与连接；收起后仍能切换主题 |
| 模型与工具 | 当前模型摘要、预读与专注阅读入口 | 按需显示引擎、模型、推理强度、智能阅读、检索和多篇对比 |
| 材料 | 输入区上方的「材料」「截图提问」 | 显示全文、当前页、范围和格式选项；取消读取保留问题 |
| 常用问题 | 输入区内的小入口 | 浮层出现在输入区上方，不增加问题框高度 |
| 输入区 | 与回复阅读外框对齐 | 收起与展开使用同一个右侧按钮，不移动目标位置 |
| 回复操作 | 回答下方的记入笔记、复制与详情 | 实际模型信息按需展开，旧记录缺少信息时明确提示 |

用户消息通过气泡区分，AI 直接显示正文，不再重复显示“你”或引擎标题。读屏仍能区分消息角色；查看模型信息不会改变会话内容。

## 阅读空间与滚动

- 回复正文与输入容器的左右外边缘一致；输入容器四角一致，不被父层裁成直角。
- 主要页面外沿通常为 10px，极窄侧栏为 8px；消息内部左右留白分别为 10px 和 14px，与外沿分开处理。
- 滚动条有稳定保留位置。气泡、中文、英文、列表、引用和代码中的可绘制文字不得进入滚动条轨道。
- 回复与输入容器之间通常留 8px，短窗口为 6px；展开工具时仍保留至少 40px 的回复内容区和可点击的发送入口。
- 输入区域过高时，其材料和编辑区域可局部滚动，不能把回复区挤为不可操作的薄条。
- 材料预览只滚正文，关闭与导出操作始终可见，不要求滚回开头。

### 流式回复与阅读锚点

`chat-view.js` 负责增量节点复用和阅读位置，不持有会话数据。

1. 位于末尾时跟随新内容；打开材料或收展输入后，维持末尾内容可见。
2. 主动上滚、选中文字或查看早期内容时暂停跟随，不强制拉回最新回答。
3. 「回到最新」恢复跟随；新建或恢复会话后按对应会话重新建立视图。
4. 布局变化前捕获可见锚点，变化期间保留它；用户主动滚动优先于自动调整。
5. 销毁面板时取消视图定时器、观察器和监听；迟到的流式回调不能更新已关闭视图。

未发送的问题、材料、选择位置和滚动位置按论文暂存在当前插件窗口内。切换论文可恢复，关闭窗口后不保留未发送草稿；已发送会话由会话仓库持久化。

## 局部定位与弹层

设置页的快速定位、提示词跳转、笔记查找及词库编辑/导入，只滚动自身可滚动容器。不得通过对内部节点调用无约束的定位方式，把 Zotero 外层侧栏一同滚走。设置快速定位在自身顶部吸附时不能裁掉文字。

主题菜单使用顶层弹层，兼容路径也必须高于工作区内容。菜单打开时清理并暂停边框追光，菜单关闭后恢复；Esc 和键盘选项循环保持可用。点击目标不得被光效、透明占位或其他按钮穿透遮挡。

局部展开采用短过渡；页面切换主要使用约 100ms 的淡入，工具收展约 140ms。交互状态应立即响应，持久化异步完成；保存失败回退到已提交偏好并提示。减少动态效果或关闭动效时立即完成状态切换。

## 单词本布局

- 本章单词只显示当前论文中的词与语境；所有单词对应个人完整词库；继续复习保留上次确认的位置。
- 极简与完整模式使用同一首行结构，一行一个词。英文、中文、个人累计次数和展开箭头保持同排。
- 展示、遮挡和揭示使用同一个释义槽；文字起点、行高和箭头位置不因切换答案状态而变化。
- 词卡与搜索框左右对齐，展开后不因滚动条出现而横移。完整模式只增加语境，不改变首行布局。
- 独立窗口复用同一词库、复习状态与主题；重复打开不清空当前搜索或详情。
- 载入失败应显示可读的恢复提示和重试/关闭操作，不能只留下白窗。

完整数据与补句流程见[单词本说明](vocabulary.md)。

## 设置与请求边界

`settings-panel.js` 管理批量设置、双提示词和词库选项的草稿、保存互斥与 Key 状态。保存时继续输入的新内容必须保留；只有确实保存过的 Key 输入才清空。Key 留空表示保留，明确点击删除才清除。保存、恢复提示词或切换主题不调用模型。

`chat-service.js` 管理一次问答的忙碌、停止与完成状态；`model-gateway.js` 负责明确模型和账号快照、协议及用量请求；`sessions.js` 管理会话、归档与失败恢复。会话准备期间也属于问答操作，停止和关闭必须覆盖准备阶段。

本机保存失败时，回答仍保留在窗口中，提供「重试保存」。该操作只重试落盘，不重新请求模型。切换历史或新建会话不能越过正在进行的问答及保存事务。

普通 ChatGPT 网页路径仍由用户在网站发送：插件只准备草稿和附件。网页专注状态可隐藏插件材料与输入区；退出时恢复布局和草稿。

## 原生验证入口

使用专用隔离配置、合成 PDF 和模拟响应，不能以真实账号资料作为夹具。按改动选择检查，不以截图相似或主观分数代替行为断言。

| 范围 | 主要检查 |
| --- | --- |
| 收展、材料、菜单和阅读锚点 | `tests/chat-interactions-native-harness.js`、`tests/chat-layout-native-harness.js` |
| 连续输出、取消和本机保存 | `tests/iteration-native-harness.js`、`tests/chat-service.test.cjs`、`tests/chat-state.test.cjs` |
| 批量设置与并发草稿 | `tests/settings-panel.test.cjs`、`tests/settings-concurrency.test.cjs`、`tests/workspace-native-harness.js` |
| 词库同槽布局与开窗 | `tests/vocabulary-window-native-harness.js`、`tests/vocabulary-native-harness.js` |
| 跨页面与缩放 | `tests/uiux-native-harness.js`、`tests/polish-native-harness.js` |
| 正常安装与同配置完整重启 | `tests/install-restart-native-harness.js` |

布局矩阵应覆盖 260/340/520px 侧栏和独立大窗、100%–200% 缩放、短窗口全展开、中文长段落、英文长词与代码。原生测试以实际边界、焦点、命中和滚动断言为准；目前不宣称跨平台、真实读屏用户或前台帧率认证。运行方式见[参与开发](../CONTRIBUTING.md#原生集成验证)。
